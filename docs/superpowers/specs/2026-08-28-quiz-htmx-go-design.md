# Квиз на htmx + Go + Postgres — дизайн

Дата: 2026-08-28

## Цель

Веб-приложение для проведения квизов. Страницы собираются на сервере,
htmx подменяет отдельные фрагменты без перезагрузки. Данные в Postgres.
Запуск одной командой через docker-compose.

## Роли и вход

Вход единый для всех — по токену. Логинов и паролей нет.

`users` — одна таблица для админов и игроков, роль в колонке `role`
(`admin` | `player`). Токен: 24 символа из `crypto/rand`, уникальный индекс.

Первый админ создаётся миграцией с известным токеном. При старте, если задана
переменная окружения `ADMIN_TOKEN`, токен админа обновляется на неё.

Сессии — `alexedwards/scs/v2` + `alexedwards/scs/pgxstore`, таблица `sessions`
в той же базе. Срок жизни — 12 часов. В сессии хранится только `user_id`.

Два middleware:
- `requireUser` — пускает любого вошедшего, иначе редирект на форму входа;
- `requireAdmin` — дополнительно проверяет роль, иначе 403.

## Сценарий игрока

1. Вводит токен на главной → список опубликованных квизов.
2. Выбирает квиз → создаётся попытка. Одна попытка на пару (квиз, игрок).
3. Отвечает на вопросы по одному, раунд за раундом, в порядке `position`.
4. Обратной связи по ходу нет. В конце — экран итогов с суммой баллов и
   пометкой, если часть ответов ещё на проверке.
5. Страница рейтинга по квизу.

## Сценарий админа

- **Игроки.** Вводит имя → генерируется токен, показывается в списке.
- **Квизы.** Квиз → раунды → вопросы. У вопроса: текст, тип
  (`choice` | `free`), `points_correct`, `points_wrong` (может быть
  отрицательным), `admin_hint`. Для `choice` — варианты с отметкой верных.
- **Публикация.** Черновик игрокам не виден. Кнопки «опубликовать» и «закрыть».
- **Проверка.** Очередь свободных ответов, ожидающих решения. В строке: вопрос,
  ответ игрока, подсказка админу, кнопки «верно» / «неверно». Нажатие начисляет
  баллы и убирает строку из очереди через htmx.

## Данные

| Таблица | Назначение |
|---|---|
| `users` | id, name, token (unique), role, created_at |
| `quizzes` | id, title, description, status (draft/published/closed), created_at |
| `rounds` | id, quiz_id, title, position |
| `questions` | id, round_id, position, kind, text, points_correct, points_wrong, admin_hint |
| `answer_options` | id, question_id, text, is_correct, position |
| `attempts` | id, quiz_id, user_id, started_at, finished_at; UNIQUE(quiz_id, user_id) |
| `responses` | id, attempt_id, question_id, option_id, free_text, is_correct, points_awarded, reviewed_at, reviewed_by; UNIQUE(attempt_id, question_id) |
| `sessions` | token, data, expiry — служебная, для scs |

Ключевая идея в `responses`: `is_correct` и `points_awarded` заполняются сразу
для вопросов с выбором и остаются NULL для свободного ввода. NULL — признак
«ждёт проверки». Рейтинг — сумма `points_awarded`, непроверенное в неё не входит.

Удаления каскадные: квиз тянет за собой раунды, вопросы, варианты.

## Подсчёт баллов

При отправке ответа:
- `choice` — сравниваем выбранный вариант с `is_correct`, ставим
  `points_correct` или `points_wrong` немедленно;
- `free` — сохраняем текст, `is_correct` и `points_awarded` остаются NULL;
- при проверке админом — проставляем `is_correct` и соответствующие баллы.

## Структура кода

Раскладка по Google Go Style Guide, пакет = одна задача.

    cmd/quiz/main.go          точка входа
    internal/config           чтение окружения
    internal/domain           структуры данных
    internal/storage          Postgres: по файлу на сущность
    internal/auth             генерация токенов, middleware
    internal/quiz             подсчёт баллов
    internal/web              роутинг, обработчики, шаблоны и статика
    migrations                SQL-миграции

Шаблоны и статика лежат в `internal/web/templates` и `internal/web/static`:
`go:embed` умеет вкладывать только файлы своего каталога, поэтому держать их
рядом с обработчиками проще, чем заводить отдельный пакет в корне.

## Зависимости

| Библиотека | Зачем |
|---|---|
| `jackc/pgx/v5` | драйвер и пул соединений Postgres |
| `alexedwards/scs/v2` | сессии |
| `alexedwards/scs/pgxstore` | хранение сессий в Postgres |
| `golang-migrate/migrate/v4` | миграции |

Роутинг — `net/http`, шаблоны — `html/template`, логи — `log/slog`.
htmx лежит файлом в `web/static`, без CDN.

## Тесты

Юнит-тесты на подсчёт баллов и генерацию токенов, без базы, плюс проверка,
что все шаблоны разбираются. Интеграционные тесты на хранилище не пишем.

## Вне объёма

Регистрация игроков, несколько админов с разными правами, таймеры на вопрос,
картинки в вопросах, редактирование отправленных ответов, повторные попытки.
